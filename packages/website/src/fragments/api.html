core · 数据模型

core 层是零依赖的数据模型与结构面：四类单元最终都编译成 AgentTool，一次 run 沉淀为一条 Trace。

导出签名摘要说明
AgentTool<I, O>{ name; description; inputSchema; strict?; run(input: I, ctx?: ToolRunContext) }模型可见工具的最小结构面。run 抛错被包成 is_error 的 tool_result 回给模型，run 不中断。
JsonSchema{ type; description?; properties?; required?; additionalProperties?; … }工具 input_schema 的 JSON Schema 子集（v1 裸 schema，不依赖 zod）。
ModelClient{ messages.stream(params) → { on('text', cb); finalMessage() } }engine 对模型端的最小结构面；Anthropic SDK 天然满足，其他 provider 适配成同一形态。params 含可选 signal（取消传播）。
ToolRunContext{ client; recorder; parentSpanId; signal? }engine 调用每个工具时注入的执行上下文，供子单元把嵌套 span 挂进当前 trace；signal 由工具自行决定是否尊重。
RecorderBackendbegin / end / event / setAttribute / snapshotTraceRecorder 面向子单元的最小记账面（core 不依赖 engine）。
Trace{ traceId; rootSpanId; spans: Span[]; status; totalUsage }一次 run == 一条 trace（traceId == runId）；totalUsage 只累加 llm.turn span（unit 的 usage 是子孙聚合，仅供展示）。
Span{ spanId; parentSpanId; kind; name; startedAt; endedAt?; status; error?; usage?; attributes; events }调用树节点；unit 名为 ${unitType}:${unitName}，llm.turn 名为模型 id。
Usage{ inputTokens; outputTokens; cacheReadTokens; cacheCreationTokens; costEstimate? }span 聚合用量；成本由 token × 单价表估算。
SpanKind'run' | 'unit' | 'llm.turn'span 层级：整次运行 / 单元调用（仅 skill 与 subagent 建）/ 每次模型往返。普通工具与 @Prompt 只记 turn 上的事件，不建 span。
UnitType'tool' | 'skill' | 'prompt' | 'subagent'四类单元，共用命名空间。
SpanEvent{ time; name; body }span 上的结构化事件（如 tool.input / tool.output / compaction / budget.exceeded）。
SpanError{ type; message; retryable }错误分类；retryable 标记 429 / 5xx / 网络类可安全重试（重试逻辑消费它）。
SpanStatus / SpanId / TraceId'ok' | 'error' / string / string基础类型别名。
TraceSink{ export(trace) → void | Promise<void> }trace 出口：run 收尾（成功 / 失败）都投递，sink 抛错被吞、不影响 run。OTLP 导出器与 metricsSink() 都天然满足它。
validateJsonSchema(schema: JsonSchema, input: unknown) → string | nullJSON Schema 子集校验（fromZod 接入时先走 zod），返回首条错误消息或 null。
combineSignals(...signals: (AbortSignal | undefined)[]) → AbortSignal合成多个中断源（调用方 / 超时 / 断连），任一触发即中止（Node 18 无 AbortSignal.any）。
Blackboard / BlackboardKey / BlackboardValue / BlackboardSeedinterface Blackboard {} 等黑板类型链路：声明合并 Blackboard 后，RunContext.get/set 与 run({ blackboard }) 种子获得键补全 + 拼写检查 + 值类型；不声明则与旧行为逐字一致（键 string、值 unknown）。
TypedSchema<T> / SchemaType<S> / SchemaInput<S>SchemaType<TypedSchema<T>> = Tschema 即单一事实来源：fromZod<T>() 返回 TypedSchema<T>，据此自动推导 result.typed 与 @Tool 方法入参类型（不匹配即编译期报错）。
AGENTIA_VERSIONstring框架版本号常量（与已发布的包版本同步）。

engine · 运行时内核

流式 manual loop：模型往返 + 递归工具调用，直到 end_turn / 循环上限 / submit_result 提交结构化结果；可取消、可重试、可按成本硬停。

导出签名摘要说明
runAgent(options: RunAgentOptions) → Promise<AgentRunResult>主循环入口；不注入 recorder 时内部新建，traceId 即 runId。
RunAgentOptions{ messages; system?; tools?; model?; … }主循环入参（逐项见下表）。ExecuteRunOptions / RunAppOptions 在它之上叠加各自的字段。
resolveDefaultModel(over?: string) → string模型缺省解析：显式参数 > AGENTIA_MODEL 环境变量 > claude-opus-5。
TraceRecorderclass：begin(kind, name, parent) / end(id, patch?) / event / setAttribute / snapshot(status)span 记账器，traceId 随实例生成。
classifyError(e: unknown) → SpanErrorSDK 异常归类：rate_limit / connection 标 retryable。
isAbortError(e: unknown) → boolean判定异常是否为中断（name === 'AbortError'）；中断不重试、不冒泡。
isSuccessStopReason(reason: AgentStopReason) → boolean「正常收尾」的唯一尺子（end_turn / stop_sequence）；run 状态机、trace 状态、子 agent 交回判定共用它。
AgentRunResult{ trace; stopReason; finalText; iterations; error?; typed? }typed 为 resultSchema 校验通过的结构化结果（模型未提交则为 undefined）。
AgentStopReason'end_turn' | 'stop_sequence' | 'max_tokens' | 'refusal' | 'pause_turn' | 'max_iterations' | 'aborted' | 'budget_exceeded' | 'tool_use_no_blocks' | 'unknown_stop_reason' | 'error'循环终止原因。aborted（被取消）与 budget_exceeded（超预算）都算失败。
DEFAULT_RETRY / RetryOptions{ maxAttempts: 3; baseDelayMs; maxDelayMs; jitter; onRetry?; isRetryable? }模型请求重试缺省参数（指数退避 + 抖动）；retry: false 关闭，单次 run 可覆盖。
ContextPolicy{ budgetTokens?; beforeTurn(messages, { iteration, model }) → Promise<messages> }上下文预算策略面：每回合发送前可编辑 / 压缩消息。
SystemParam / SystemTextBlockstring | SystemTextBlock[]system 参数：纯文本，或带 cache_control breakpoint 的可缓存块数组。
createBudgetGuard / BudgetGuard(opts?: BudgetGuardOptions) → { check(trace) → 'tokens' | 'cost' | null }成本硬管控底座（每回合记账后判）；也可以只拿它自己记账。
BudgetGuardOptions / BudgetSnapshot{ maxTotalTokens?; maxCostUsd?; onExceed? } / { kind; limit; actual; totalTokens; costUsd }超限快照同时记进 run 根的 budget.exceeded 事件并回调 onExceed。
mapWithConcurrency(items, limit, fn) → Promise<R[]>有界并发 map，结果顺序与输入一致；limit 非正 / 非有限 = 不限（旧行为）。同回合并行工具的底座。

RunAgentOptions 选项

选项类型说明
messages（必填）MessageParam[]初始消息；由调用方给 user 起始消息。
systemSystemParam顶层 system（SystemPrompt 产物）；稳定内容放在第一个 breakpoint 前。
toolsAgentTool[]主 agent 可调工具菜单（裸 JSON schema）。
modelstring缺省走 resolveDefaultModel。
maxTokensnumber流式请求的 max_tokens，给足避免中途截断。
maxIterationsnumber循环安全上限，防止无限 tool 往返。
clientModelClient缺省 new Anthropic()（读环境变量）；多模型场景注入适配 client。
recorderTraceRecorderrun 层复用注入；不注入则内部新建。
onText(delta: string) => void文本增量回调（终端 / SSE 用）。
runNamestring写入 trace 根 span 名。
contextPolicyContextPolicy每回合发送前的上下文预算策略（compaction / context editing）。
resultSchemaJsonSchema给出后追加隐藏工具 submit_result，模型提交校验通过的结果写入 result.typed 并结束循环。
signalAbortSignal中断信号：中止则取消在飞请求，run 以 stopReason='aborted' 收尾（不抛异常）。
retryRetryOptions | false模型请求重试策略；缺省开启（maxAttempts=3）。只重试「本次尝试未产出任何文本」的失败。
maxTotalTokensnumber整条 run（含子 agent）累计 token 上限；超限以 budget_exceeded 收尾（算失败）。不是硬实时（一回合记账完才判）。
maxCostUsdnumber累计成本上限（美元）；依赖模型在价格表内，不在表里时成本恒 0、这条护栏不触发。
toolTimeoutMsnumber单工具执行超时（毫秒），缺省 0 = 不限。超时不杀 run：该条 tool_result 记 is_error。⚠️ 是「放弃等待」不是取消。
maxToolConcurrencynumber同一回合内并行工具上限；缺省 Infinity（全并行）。
systemVersionstring写进 run 根 attribute system.version；走 app.run 时由 SystemPrompt({ version }) 自动带上。

engine · 长上下文策略

预算驱动的上下文护栏：估算 ≤ 预算走快路径原样放行；超预算先 context editing（不调模型）；仍超且有 summarize 才 compaction，并带滞回避免每回合反复压缩。

导出签名摘要说明
createBudgetPolicy(opts?: BudgetPolicyOptions) → ContextPolicy上述三段降级的开箱实现；框架不替你造 token，可注入按 /count_tokens 的 estimate。
BudgetPolicyOptions{ budgetTokens?=60000; keepToolPairs?=1; keepRecent?=20; estimateTokens?; editBeforeCompact?=true; summarize?; compactEvery?=1 }keepToolPairs 管 context editing（按对数），keepRecent 管 compaction（按条数）；summarize 提供才允许 compaction。
trimToolPairs(messages, opts?: TrimOptions) → messagescontext editing：丢弃超出 keepToolPairs（缺省 1 对）的旧 tool_use→tool_result 对；非严格交替历史整体放弃裁剪。
traceToMessages(trace, opts?: ReplayOptions) → MessageParam[]trace 重放基底：把完成的 run 还原成可喂回模型的对话（角色交替合法、tool 对配对、末条为 user、可截断）。
compactMessages(messages, opts: CompactOptions) → Promise<messages>compaction：旧前缀经 summarize 摘要，只留最近 keepRecent（缺省 20 条）。
defaultEstimateTokens(text: string) → numberCJK 感知的 token 启发式估算（预算决策用，非精确记账）。
estimateMessages(messages, estimate?) → number整组消息 token 估算。
renderMessages(messages) → string消息渲染成纯文本，作摘要器输入。
TrimOptions / CompactOptions / ReplayOptions{ keepToolPairs? } / { keepRecent?; summarize } / { includeToolIO?; maxEventChars? }上述函数的选项类型（注意单位不同：keepToolPairs 是对数，keepRecent 是条数）。

run · 生命周期与触发

一次 run 的完整生命周期（RunContext + recorder + 记忆水合/回写 + 会话历史），以及同步 RPC、异步任务、定时调度三类触发 —— 共用同一份输入契约，换宿主不换语义。

导出签名摘要说明
executeRun(options: ExecuteRunOptions) → Promise<{ run; result }>run 生命周期入口：RunContext 作用域内跑 runAgent，finish / fail 收口，收尾投递 sinks。
ExecuteRunOptionsRunAgentOptions & { idempotencyKey?; contextInit?; memory?; session?; rethrow?; sinks? }memory：run 开始把 store.load(keys) 水合进 blackboard（用户种子优先），结束回写；session：对话历史读写（与前者正交）。
Runclass：start() / finish(result) / fail(error) / toMeta()run 状态机（queued → running → succeeded/failed）；runId == recorder.traceId。
RunContextclass：static current() / get(key) / set(key, value) / has / delete / keysrun 内 blackboard，AsyncLocalStorage 传播，不用全局单例。键类型随 Blackboard 声明合并收窄（未声明为 string）。
withRunContext(ctx: RunContext, fn) → T | Promise<T>在指定 ctx 作用域内执行 fn（返回类型随 fn：同步 fn 给 T）。
RunMeta / RunStatus{ runId; status; idempotencyKey?; createdAt; startedAt?; finishedAt?; error? } / 'queued' | 'running' | 'succeeded' | 'failed'运行记录与状态。
SystemPromptclass：new SystemPrompt({ version? })；add(name, text, stable?) / add(section) / build({ cache? })分段组装 system：stable 段进可缓存前缀打 ephemeral breakpoint，volatile 段放其后；version 自动写入 run 根 system.version。
SystemPromptOptions / SystemSection{ version? } / { name; text; stable? }构造选项与段落；stable=false 不进可缓存前缀。
SessionStore / InMemorySessionStoreinterface：load(id) / append(id, messages)跨 run 的对话历史（append-only），与 MemoryStore（键值黑板）正交，可同时用；只有跑成功的轮次才回写。
normalizeMessages(input: RunInput | unknown) → MessageParam[]任意任务入参（string / messages / { prompt | text | messages }）规范成 messages；空数组抛错。
RunInputstring | MessageParam[] | { prompt?; text?; messages? }transport 层接受的原始入参形态。
RunSpec{ messages; options?; source? }一次任务的规范化入参；source 标记触发来源（sync / async / schedule:<id>）。
RunInvocationOptions{ model?; maxTokens?; maxIterations?; client?; onText?; signal?; retry?; blackboard?; contextPolicy?; idempotencyKey?; rethrow?; tools?; maxTotalTokens?; maxCostUsd?; toolTimeoutMs?; maxToolConcurrency? }单次 run 的调用参数，三类触发共用（不含不可序列化的 store / session —— 那几个只在程序内直调时可用）。
runSync / createSyncHandler(app, input, opts?) / (app) → (input, opts?) => …同步 RPC：规范化入参后直接 app.run。
AsyncRunnernew AsyncRunner(app, { client?, store?, concurrency?, runTimeoutMs?, taskSinks? })：submit / resumePending(opts?) / drain(opts?) / inFlight / isDraining提交即返回任务记录、后台执行；同幂等键未失败任务 last-wins 去重。drain() = 拒新单 → 等在飞收尾（超时返回 false，未完成任务留在 store 里）。
AsyncRunnerOptions / ResumePendingOptions{ …; runTimeoutMs?; taskSinks? } / { staleAfterMs? }runTimeoutMs 到点真中止在飞 run；resumePending 靠 staleAfterMs + ownerId 跳过本进程记录。
TaskSink{ onFinished(rec: TaskRecord) }任务完成回调：达终态后逐个 await 投递（抛错被吞），先通知再递减在飞计数。
AppCallable{ name; run(messages, opts?) }应用最小调用面（run 层不向上依赖 toolkit）。
Scheduler / ScheduleHandle / ScheduleEveryOptionsnew Scheduler(runner)：every(intervalMs, input, opts?) / at(when, input, opts?)周期 / 定点触发，到点转为异步任务提交；返回 ScheduleHandle { id, cancel() }；非法间隔 / 非法日期直接抛错。
TaskStoreinterface：save / get / byIdempotency / list / clear任务记录存储面（同步或异步实现皆可，返回 MaybePromise）；byIdempotency 为 last-wins 去重依据。
TaskRecord{ taskId; status; idempotencyKey?; spec: RunSpec; runId?; ownerId?; createdAt; startedAt?; … }任务记录；完成后回填 runId（== traceId）。
InMemoryTaskStoreclass（TaskStore）：{ maxRecords? }Map 实现：测试与缺省场景用；超上限从最旧已终态记录起淘汰（在飞记录永不淘汰）。
FileTaskStorenew FileTaskStore(file)JSONL 一行一快照落盘；宿主重启后 resumePending() 续跑 queued/running。
SqliteTaskStorenew SqliteTaskStore(path)node:sqlite 落库（WAL 读写不互斥），支持 ':memory:'。

MaybePromise<T>T | Promise<T>同步 / 异步实现统一形态（调用方 await 兼容两种）。

run · 宿主与导出

同一份应用一行接入 HTTP（含鉴权缝、优雅停机、健康检查）；trace 可导出到任何 OTLP 收集器或自建 sink；OpenAI 兼容端点一行接入多模型。

导出签名摘要说明
createHttpHandler(app: AppCallable, opts?: HttpHandlerOptions) → HttpHandlernode:http 接入：POST /run（同步 / SSE）、POST /tasks（异步）、GET /tasks/:id（轮询）、GET /healthz。返回值可直接传给 http.createServer，另挂 drain() 与 runner。
HttpHandlerOptions{ runner?; authenticate?; maxConcurrentRuns?=32; maxBodyBytes?=1MiB; exposeErrors?=false }authenticate 拦在入口、读 body 之前（除 /healthz 外的所有路径）；超并发回 503 + Retry-After；exposeErrors 关时 500 只回通用文案。
HttpHandler((req, res) => Promise<void>) & { drain(opts?) → Promise<boolean>; runner }停机：drain() 拒新单 → 等在飞收尾 → 超时强制收口 SSE 流；未完成任务留在 store 里。
HttpExceptionnew HttpException(status, body)鉴权钩子里抛它即按其 status / body 回（想回 403 就抛 403）；抛其它错误回 401 且原文只进服务端日志。
HealthResponse{ ok; inFlight; uptimeMs; draining }GET /healthz 的返回：不鉴权、停机中也回 200；ok 恒 true（能回响应即进程活着），就绪与否看 draining。
RunHttpResponse / TaskSubmitBody{ runId; …result } / { input; options?; idempotencyKey? }HTTP 契约类型。
registerDefaultTraceSink(sink: TraceSink) → void注册全局默认 sink（createApp 构造期快照合并，已建应用不受后续注册影响）。
createOtlpExporter({ endpoint, headers?, serviceName? }) → { export(trace) → Promise<void> }trace 导出到任意 OTLP/HTTP 收集器（缺省 service.name 为 'agentia'）；节点 span 展开成 attributes + events，零依赖。
createOpenAIClient(opts?: { apiKey?; baseURL?; fetchImpl?; stream? }) → ModelClientOpenAI 兼容端点（含 DeepSeek 等）适配成 ModelClient：真流式、图片块转 image_url、转发 signal。stream: false 退回一次性。
MemoryStoreinterface：load(keys) / save(entries)跨 run 记忆存储面（可同步或异步实现）。
InMemoryMemoryStoreclass（MemoryStore）Map 实现：进程内，无持久化。

integrations · MCP 与指标

外部系统适配层，只依赖 core，零运行时依赖 —— 可选能力一律 duck-typed（与 RedisLike 同款范式）。

导出签名摘要说明
mcpTools(client: McpClientLike, opts?: McpToolsOptions) → Promise<AgentTool[]>把 MCP server 的 tools/list 映射成框架工具，可直接进 createApp({ tools })；与本地 @Tool 同池（同过中间件、同进重名查重）。
McpClientLike{ listTools(); callTool(name, args) }MCP client 的最小结构面：任意实现它的对象都能接，框架不 import MCP SDK；stdio / HTTP 传输在独立包或你自己的代码里。callTool 失败请抛错（框架会包成 is_error）。
McpToolInfo{ name; description?; inputSchema? }tools/list 条目的结构面子集；inputSchema 已是 JSON Schema → 原样当 input_schema 用。
McpToolsOptions{ prefix?; server?; timeoutMs?=60000 }缺省前缀 mcp_<server>_（没给 server 时 mcp_）；timeoutMs 是单次调用超时（放弃等待，非取消）。
MCP_DEFAULT_TIMEOUT_MS60000桥的缺省单次调用超时。
metricsSink(opts?: MetricsSinkOptions) → MetricsSink进程内指标累加器，天然满足 TraceSink → createApp({ sinks: [metricsSink()] }) 即接入，零新出口。
MetricsSinkTraceSink & { snapshot(); render(); reset() }snapshot 给数值，render 给 Prometheus 文本（/metrics 直接回它），reset 清空累计。
MetricsSinkOptions / MetricsSnapshot{ export?: 'prometheus' | 'otlp'; windowSize?=1024; prefix?='agentia_' } / { runs; failed; latencyP50; latencyP95; tokens; costUsd }tokens 口径 = 四类之和（与 BudgetGuard 一致）；分位是窗口内精确值（非原生 histogram）；export: 'otlp' 尚未实现 → 构造期抛错。

eval · 回归断言

叶子消费模块（只依赖公共面、零反向依赖）：把测试里的 mock client 提升为一等能力，让「改 prompt / 换模型 / 加工具之后有没有回归」变成断言，而不是靠人眼。断言源就是既有的 Trace。

导出签名摘要说明
scriptedClient(steps: ScriptedStep[]) → ModelClient按脚本依次返回模型响应，并真的把文本块经 on('text') 吐出去（onText / SSE 链路按真实路径走）。步骤在 finalMessage 成功后才前进 → 抛错的步骤在重试时重放同一步。
ScriptedStepRecord<string, unknown> | (params) => message一步脚本：直接给响应对象，或按本次请求参数现算（可 throw 模拟 429 / 网络失败）。脚本耗尽即抛错。
defineEval<T>(def: EvalDefinition<T>) → { name; run() → Promise<EvalReport> }定义「用例 + 断言」。run() 不抛（用例失败进报告，一次跑完能看到所有回归），只有应用建不起来才冒泡。
EvalDefinition{ name; app; cases; expect }app 一轮只建一次（用例间复用装配）；expect 抛错 = 该用例失败。
EvalCase{ name?; input; client; opts? }一个用例；opts 透传 app.run（注入 resultSchema 才能断言 result.typed）。
EvalContext{ trace: Trace }断言上下文（与 result.trace 同一份）。
EvalReport{ name; total; passed; failed; ok; cases: EvalCaseReport[] }报告；ok 全通过才 true（total=0 视为通过）。接 CI 只看 report.ok。
EvalCaseReport{ name; ok; stopReason?; error?; trace? }失败 case 带完整 trace —— 排查回归就看它。

container · 显式 DI

显式 provider 注册，覆盖式语义（后注册覆盖先注册）；resolve 单例缓存并做循环依赖检测；重新注册会传递失效下游缓存。

导出签名摘要说明
Containerclass：register(...providers) / has(token) / resolve<T>(token)DI 容器；register 返回 this 可链式。
Tokenstringprovider 注册键。
ProviderValueProvider | ClassProvider | FactoryProvider三种 provider 形态的联合。
ValueProvider{ provide; useValue }直接给值。
ClassProvider{ provide; useClass; deps? }类实例化；deps 按序注入构造器参数。
FactoryProvider{ provide; useFactory; deps? }工厂函数；deps 与 useFactory 形参一一对应（形参类型自由，不会因逆变被拒）。

toolkit · 声明式单元与装配

装饰器声明四类单元，createApp 装配：DI 注册 → 扫描收集菜单 → 装配期静态校验（菜单查重、tools 引用存在性、toolSources 指向、DI 循环依赖）。

导出签名摘要说明
createApp(opts: AppOptions) → AgentApp；带 discover 时 → Promise<AgentApp>装配应用；目录发现走动态 import，故返回 Promise。
AppOptions{ name?; providers?; modules?; discover?; system; model?; maxTokens?; maxIterations?; contextPolicy?; retry?; maxTotalTokens?; maxCostUsd?; toolTimeoutMs?; maxToolConcurrency?; toolSources?; tools?; middleware?; sinks? }system 必填：SystemPrompt 实例（自动打缓存）或拼好的 SystemParam。tools 是裸工具直进主菜单（MCP 桥等动态工具走这里，同过中间件与查重）；sinks 是 trace 出口。
AgentAppclass：run(messages, opts?: RunAppOptions) → Promise<AgentRunOutput>；tools；container装配产物；run 每执行一次从 SystemPrompt 重建 system，保证 volatile 新鲜。
RunAppOptionsRunInvocationOptions & { system?; resultSchema?; session? }单次调用参数：可覆盖 system、给结构化结果 schema、传会话存储（session 不可序列化，故只在程序内直调时可用）。
AgentRunOutput{ run: Run; result: AgentRunResult }app.run 的返回。
defineModule / AgentModule(m: AgentModule) → AgentModule / { providers; middleware? }第三方能力包约定：providers 先于应用级注册（同 token 应用级覆盖），middleware 拼在更外层；defineModule 为 identity 函数。
Tool@Tool(spec: ToolSpec) 方法装饰器类方法即工具：入参按 schema 先校验再执行。
ToolSpec{ name?; description; schema: JsonSchema; strict? }name 缺省取方法名；strict 需 additionalProperties:false + required 齐全；schema 给 fromZod<T> 时方法签名会被校验。
collectTools(instance: object) → AgentTool[]沿原型链扫描 @Tool 方法并绑定实例。
Skill@Skill(spec: SkillSpec) 方法装饰器方法体是确定性脚本；模型调用只在显式 ctx.llm() 时发生，记在 skill 自己的 unit span 下。
SkillSpec{ name?; description; schema?; model?; maxTokens?; maxIterations?; tools? }tools 为容器 provider token 列表（ctx.llm() 可调）。
SkillContext{ model?; llm(opts: SkillLlmOptions) → Promise<SkillLlmResult> }受限子运行句柄：每次 llm() 在 unit span 下开一轮独立 agent 循环。
SkillLlmOptions / SkillLlmResult{ prompt?; messages?; system?; model?; maxTokens?; maxIterations? } / { text; stopReason }prompt 与 messages 二选一；system 接受 string 或 SystemPrompt。
collectSkills / skillToTool(instance) → SkillUnit[] / (unit, resolveTools) → AgentTool扫描 @Skill 方法 / 编译成主 agent 菜单项。
SkillUnit{ name; description; inputSchema; spec; invoke(input, ctx) }含绑定实例的方法执行器。
SubAgent@SubAgent(spec: SubAgentSpec) 方法装饰器方法体不执行：框架按 system 另起隔离循环，中间过程不外泄，只有最终报告回流。
SubAgentSpec{ name?; description; schema; system; tools?; model?; maxTokens?; maxIterations? }system 支持 string / SystemPrompt / (task) => SystemParam（动态拼，框架不附加）；tools 为 provider token 列表。
collectSubAgents / subagentToTool(instance) → SubAgentUnit[] / (unit, resolveTools) → AgentTool扫描 @SubAgent 方法 / 编译成 AgentTool（子循环复用 ctx.client 与 recorder）。
SubAgentUnit{ name; description; inputSchema; spec }子代理单元元数据。
Prompt@Prompt(spec: PromptSpec) 方法装饰器纯文本资产编译成无副作用的拉取型工具；每次调用重算（volatile 语义）。
PromptSpec{ name?; description; schema? }description 写清何时该拉取，模型据此决定调用；schema 缺省空对象（无参资产）。
collectPrompts(instance: object) → AgentTool[]扫描 @Prompt 方法（static 方法亦可）。
asset(base: string | URL, rel: string) → stringasset(import.meta.url, './system.md') 相对单元目录读文本资产；每次调用现读不缓存。
discoverProviders(dir: string) → Promise<Provider[]>目录约定扫描 units/<name>/index.ts：default export 为类 / Provider / Provider[]，类以文件夹名为 token 注册。
applyMiddleware(tools: AgentTool[], middleware: UnitMiddleware[]) → AgentTool[]洋葱模型包裹整个菜单（链序 = 注册顺序，先注册最外层）；链为空原样返回，零开销。
UnitMiddleware(call: UnitCall, next: UnitNext) => unknown单元调用前后横切（鉴权 / 限流 / 缓存 / 审计 / 配额）；不调 next 即短路，抛错按单元失败处理。
UnitCall / UnitNext{ unit; input; ctx? } / (input?) => unknown入参 schema 校验已过；next(newInput) 可改写入参；连调两次会抛错。
fromZod(jsonSchema: JsonSchema, zod: unknown) → JsonSchemazod 可选接入（peer）：校验走 zod safeParse（结构面识别，框架不 import zod），错误路径原样回给模型自我修正。
