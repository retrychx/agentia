core · 数据模型

core 层是零依赖的数据模型与结构面：四类能力最终都编译成 AgentTool，一次 run 沉淀为一条 Trace。

导出签名摘要说明
AgentTool<I, O>{ name; description; inputSchema; strict?; approval?: 'required'; run(input: I, ctx?: ToolRunContext) }模型可见工具的最小结构面。run 抛错被包成 is_error 的 tool_result 回给模型，run 不中断。approval: 'required'（HITL）：每次调用先挂起等人工审批（回合级全有或全无），批准/拒绝经 AsyncRunner.approve / POST /tasks/:id/approve 到达后恢复。

MessageParam / ContentBlockParam / TextBlockParam / ImageBlockParam / ToolUseBlockParam / ToolResultBlockParam / Role / CacheControl / ToolParam{ role; content: string | ContentBlockParam[] } 等请求侧消息类型族（自有公共类型，snake_case 与 Anthropic Messages API 逐字对齐、与 @anthropic-ai/sdk 结构兼容 —— 双向兼容由类型门禁钉住）。ContentBlockParam 联合含 { type: string } 兜底成员：厂商新块型原样携带，不丢内容。ToolParam 避让 @Tool 装饰器命名。

ApprovalDecision{ approved; reason?; decidedBy?; decidedAt?; requestedAt? }人工审批决定（HITL），以 tool_use_id 为键：RunAgentOptions.approvals / RunInvocationOptions.approvals / TaskRecord.approvals（随任务落库，重启不丢）。decidedAt 缺省由框架填；requestedAt 是挂起时刻（框架回填，trace 的 approval.decided 事件据此算 waitedMs）。

Trace{ traceId; rootSpanId; spans: Span[]; status; totalUsage }一次 run == 一条 trace（traceId == runId）；totalUsage 只累加 llm.turn span（capability 的 usage 是子孙聚合，仅供展示）。
Span{ spanId; parentSpanId; kind; name; startedAt; endedAt?; status; error?; usage?; links?; attributes; events }调用树节点；capability 名为 ${capabilityType}:${capabilityName}，llm.turn 名为模型 id。links 是跨 trace 链路（v1 只出现在 run 根，见 TraceContext）；没记 link 的 span **没有这个键**（不是空数组）。

SpanEvent{ time; name; body }span 上的结构化事件（如 tool.input / tool.output / compaction / budget.exceeded）。
SpanError{ type; message; retryable }错误分类；retryable 标记 429 / 5xx / 网络类可安全重试（重试逻辑消费它）。
SpanStatus / SpanId / TraceId'ok' | 'error' / string / string基础类型别名。
TraceContext / SpanLink{ traceId: string; spanId?: string } / { traceId; spanId? }跨进程 / 跨服务关联：调用方（网关 / 队列消费者 / 上游服务）把它自己的 span 标识作为 RunInvocationOptions.traceContext 传进来，本次 run 的根 span 记成一条 SpanLink（OTLP 导出即标准 span links）。不改 traceId == runId —— run 仍是自己的新树，上游是被链接而不是被继承，所以调用树永远自洽、因果仍可查。
parseTraceparent(value: string | null | undefined) → TraceContext | undefined解析 W3C traceparent 头（00-<32位trace>-<16位span>-01）成 TraceContext。非法 / 缺失 / 版本 ff / 全零 id / 位宽不符一律返回 undefined（不抛）：链路是观测行为，不该把业务请求打成 400。createHttpHandler 在 POST /run 与 POST /tasks 上自动用它。
currentTraceparent() → string | undefined出站链路传播：当前调用期的 W3C traceparent（00-<32位trace>-<16位span>-00），带给出站请求，下游就能关联到具体 span（回合 / 能力调用粒度，而不是整次 run）。不在 run 内、或在 run 根 span 打开之前（contextInit / 记忆水合）返回 undefined；flags 恒 00（本框架不采样）。与 parseTraceparent 对称：一个解析、一个生成，共用同一份 id 投影。只给读取器 —— 框架不创建出站请求，注入那一行由宿主的 fetch / metadata 自己写。
TraceSink{ export(trace) → void | Promise<void> }trace 出口：run 收尾（成功 / 失败）都投递，sink 抛错被吞、不影响 run。OTLP 导出器与 metricsSink() 都天然满足它。
TraceRecordEvent{ type: 'span.begin' | 'span.end' | 'span.event' | 'span.attribute' | 'span.link'; seq; … }增量记账出口的事件形状（onTraceEvent 的回调参数）：run 进行中逐笔给，给「等不了收尾」的消费者（进度面板 / SSE / 异步任务流）。与 TraceSink 是两条缝，不是替代 —— sink 收尾拿整棵、本回调运行期逐笔给且不保证送达。载荷是增量 + 此刻的拷贝；按 seq 升序折回必须逐字等于收尾时的 trace。
Score{ name; value; source?; comment? }质量评分（R7 质量闭环）：LLM-judge / 人工标注 / eval 结论挂到 trace 上；约定 value 为 0–1（布尔结论用 0/1），source 记评分来源（eval 名 / 'human' / judge 模型 id）。
attachScore(trace: Trace, score: Score) → void把评分挂到 trace 根 span（一条 score 事件，body 即 Score）；评分通常来自 run 之外，故走事件而非 span 字段。出口映射：OTLP 译为 gen_ai.evaluation.result，metricsSink 聚合为 agentia_score 指标族。
validateJsonSchema(schema: JsonSchema, input: unknown) → string | nullJSON Schema 子集校验（fromZod 接入时先走 zod），返回首条错误消息或 null。
combineSignals(...signals: (AbortSignal | undefined)[]) → AbortSignal合成多个中断源（调用方 / 超时 / 断连），任一触发即中止（Node 18 无 AbortSignal.any）。
Blackboard / BlackboardKey / BlackboardValue / BlackboardSeedinterface Blackboard {} 等黑板类型链路：声明合并 Blackboard 后，RunContext.get/set 与 run({ blackboard }) 种子获得键补全 + 拼写检查 + 值类型；不声明时键为 string、值为 unknown。

engine · 运行时内核

流式 manual loop：模型往返 + 递归工具调用，直到 end_turn / 循环上限 / submit_result 提交结构化结果；可取消、可重试、可按成本硬停。

导出签名摘要说明
runAgent(options: RunAgentOptions) → Promise<AgentRunResult>主循环入口；不注入 recorder 时内部新建，traceId 即 runId。
RunAgentOptions{ messages; system?; tools?; model?; … }主循环入参（逐项见下表）。ExecuteRunOptions / RunAppOptions 在它之上叠加各自的字段。
resolveDefaultModel(over?: string) → string模型缺省解析：显式参数 > AGENTIA_MODEL 环境变量 > claude-opus-5。
TraceRecorderclass：begin(kind, name, parent) / end(id, patch?) / event / setAttribute / snapshot(status) / usage()span 记账器，traceId 随实例生成。usage() 与 snapshot().totalUsage 同口径但不拷 spans/events（预算护栏每回合判两次，走这条）。
TraceLimits{ maxEvents? }记账的数量上限：整条 trace 的事件总数闸（与管正文长度的 maxEventChars 正交）。超限即停止记账，并在交付时于 run 根写一笔 trace.truncated{droppedEvents, limit} —— 缺口位置可预测（尾巴）且有计数。缺省不设（全量记账是本框架的承诺）；0 = 一条都不记（仍有计数）。坏值在 run 入口抛 TypeError。
TraceRecorderOptions{ maxEvents? }new TraceRecorder(opts) 的构造项（与 TraceLimits.maxEvents 同一个闸；闸门在构造期生效，没有「前几条没算进闸」的窗口）。
classifyError(e: unknown) → SpanErrorSDK 异常归类：timeout / rate_limit / connection 三类都标 retryable；超时单列一类，便于按类型分流告警与重试策略。
isAbortError(e: unknown) → boolean判定异常是否为中断（name === 'AbortError'）；中断不重试、不冒泡。
isSuccessStopReason(reason: AgentStopReason) → boolean「正常收尾」的唯一尺子（end_turn / stop_sequence）；run 状态机、trace 状态、子 agent 交回判定共用它。
AgentRunResult{ trace; stopReason; finalText; iterations; error?; typed?; suspendedMessages?; pendingApprovals? }typed 为 resultSchema 校验通过的结构化结果（模型未提交则为 undefined）。stopReason === 'awaiting_approval'（HITL 挂起）时 suspendedMessages 是完整消息历史（末尾为含未决 tool_use 的 assistant 消息）、pendingApprovals 是待决 tool_use_id 列表 —— 把它俩连同 approvals 决定喂回 runAgent / app.run 即恢复执行。
AgentStopReason'end_turn' | 'stop_sequence' | 'max_tokens' | 'refusal' | 'pause_turn' | 'max_iterations' | 'aborted' | 'budget_exceeded' | 'tool_use_no_blocks' | 'awaiting_approval' | 'unknown_stop_reason' | 'error'循环终止原因。aborted（被取消）与 budget_exceeded（超预算）都算失败；awaiting_approval（HITL 挂起）不算成功也不算失败（非终态，trace 记 ok）。
DEFAULT_RETRY / RetryOptions{ maxAttempts: 3; baseDelayMs; maxDelayMs; jitter; onRetry?; isRetryable? }模型请求重试缺省参数（指数退避 + 抖动）；retry: false 关闭，单次 run 可覆盖。
ContextPolicy{ budgetTokens?; beforeTurn(messages, { iteration, model }) → Promise<messages> }上下文预算策略面：每回合发送前可编辑 / 压缩消息。
SystemParam / SystemTextBlockstring | SystemTextBlock[]system 参数：纯文本，或带 cache_control breakpoint 的可缓存块数组。
createBudgetGuard / BudgetGuard(opts?: BudgetGuardOptions) → { check({ totalUsage }) → 'tokens' | 'cost' | null }成本硬管控底座（每回合记账后判）；也可以只拿它自己记账。入参只收 totalUsage —— 传整份 Trace 也行（结构上满足），但引擎走的是 recorder.usage() 的廉价视图，不拷 spans。
BudgetGuardOptions / BudgetSnapshot{ maxTotalTokens?; maxCostUsd?; onExceed? } / { kind; limit; actual; totalTokens; costUsd }超限快照同时记进 run 根的 budget.exceeded 事件并回调 onExceed。
DEFAULT_PRICING / buildPricingRecord<string, ModelPricing> / (overrides?) → Record<string, ModelPricing>内置价格表（6 个 Claude 型号）与合并函数：priceOverrides 覆盖同名项或给非 Anthropic 模型定价（如 { 'deepseek-chat': { in: 0.27, out: 1.10 } }）。非法单价构造期抛错 —— 不让它悄悄算出 NaN 成本、把 maxCostUsd 变成永不触发的摆设。
ModelPricing{ in: number; out: number }模型单价（美元 / 1M tokens）。
mapWithConcurrency(items, limit, fn) → Promise<R[]>有界并发 map，结果顺序与输入一致；limit 非正 / 非有限 = 不限。同回合并行工具的底座。

maxToolConcurrencynumber同一回合内并行工具上限；缺省 Infinity（全并行）。
systemVersionstring写进 run 根 attribute system.version；走 app.run 时由 SystemPrompt({ version }) 自动带上。

engine · 长上下文策略

预算驱动的上下文护栏：估算 ≤ 预算走快路径原样放行；超预算先 context editing（不调模型）；仍超且有 summarize 才 compaction，并带滞回避免每回合反复压缩。

导出签名摘要说明
createBudgetPolicy(opts?: BudgetPolicyOptions) → ContextPolicy上述三段降级的开箱实现；框架不替你造 token，可注入按 /count_tokens 的 estimate。跨回合只对新增消息计 token（历史只追加时不重算前缀）。
BudgetPolicyOptions{ budgetTokens?=60000; keepToolPairs?=1; keepRecent?=20; estimateTokens?; editBeforeCompact?=true; summarize?; compactEvery?=1 }keepToolPairs 管 context editing（按对数），keepRecent 管 compaction（按条数）；summarize 提供才允许 compaction。
trimToolPairs(messages, opts?: TrimOptions) → messagescontext editing：丢弃超出 keepToolPairs（缺省 1 对）的旧 tool_use→tool_result 对；非严格交替历史整体放弃裁剪。
traceToMessages(trace, opts?: ReplayOptions) → MessageParam[]trace 重放基底：把完成的 run 还原成可喂回模型的对话（角色交替合法、tool 对配对、末条为 user、可截断）。
forkMessages(trace, opts: ForkReplayOptions) → MessageParam[]分叉重放：在主循环第 atTurn 回合（0-based；直属 run 根的 llm.turn，子 agent 嵌套回合不算，与 harvest 同口径）之前截断，只重放分叉点前的真实历史，再拼上 append 的新消息（通常是改写过的新 user 消息）——「从第 N 回合换个问法重跑」的基底，喂回 app.run / runAgent。越界抛可读错误。与 traceToMessages 同一份有损边界（assistant 文本为标注占位、原始输入不入 trace），不是续跑。
diffTraces(a, b, opts?: TraceDiffOptions) → TraceDifftrace diff（A/B 比对）：同输入换模型 / 换 prompt 跑两条 run，比出 run 级 summary（status / totalUsage / 根 attributes —— 模型差第一眼就在 attributes.model）+ 逐 span 字段级差异。纯函数。配对键：llm.turn 忽略 name（name 是模型 id，按 name 配对会把两侧全报缺失），capability 按 kind:name；缺侧子树不下钻（一条缺侧记录代表整支）；缺省忽略墙钟（ignoreTiming:false 时改比时长，绝对时间戳永不比）。
TraceDiff / SpanDiff / DiffEntry{ equal; summary: DiffEntry[]; spans: SpanDiff[] } / { path; a?; b?; fields: DiffEntry[] } / { field; a; b }diffTraces 的产物：summary 是第一眼视图，spans 只收有字段差或缺侧的 span（配平且全同的不出现）；path 是配对路径（run:<name>/llm.turn#<i>/capability:<name>），字段差逐条 { field, a, b }。
TraceDiffOptions / ForkReplayOptions{ ignoreTiming? } / ReplayOptions & { atTurn; append? }ignoreTiming 缺省 true（A/B 不关心时序）；atTurn 合法范围 0..主循环回合数-1，append 缺省不追加。分叉的 blackboard 种子由调用方经 RunInvocationOptions.blackboard 自带（trace 不记 blackboard）。
compactMessages(messages, opts: CompactOptions) → Promise<messages>compaction：旧前缀经 summarize 摘要，只留最近 keepRecent（缺省 20 条）。
defaultEstimateTokens(text: string) → numberCJK 感知的 token 启发式估算（预算决策用，非精确记账）。
estimateMessages(messages, estimate?) → number整组消息 token 估算。每次调用都全量计算 —— 需要每回合反复估同一段历史时，用预算策略（内部走增量计数）而不是直接调它。
renderMessages(messages) → string消息渲染成纯文本，作摘要器输入。

AgentRunOutput{ run: Run; result: AgentRunResult }app.run 的返回。
defineModule / AgentModule(m: AgentModule) → AgentModule / { providers; middleware? }第三方能力包约定：providers 先于应用级注册（同 token 应用级覆盖），middleware 拼在更外层；defineModule 为 identity 函数。
Tool@Tool(spec: ToolSpec) 方法装饰器类方法即工具：入参按 schema 先校验再执行。
ToolSpec{ name?; description; schema: JsonSchema; strict?; approval?: 'required' }name 缺省取方法名；strict 需 additionalProperties:false + required 齐全；schema 给 fromZod<T> 时方法签名会被校验；approval（HITL）声明后每次调用先挂起等人工审批。
collectTools(instance: object) → AgentTool[]沿原型链扫描 @Tool 方法并绑定实例。
Skill@Skill(spec: SkillSpec) 方法装饰器方法体是确定性脚本；模型调用只在显式 ctx.llm() 时发生，记在 skill 自己的 capability span 下。
SkillSpec{ name?; description; schema?; model?; maxTokens?; maxIterations?; tools? }tools 为容器 provider token 列表（ctx.llm() 可调）。
SkillContext{ model?; llm(opts: SkillLlmOptions) → Promise<SkillLlmResult> }受限子运行句柄：每次 llm() 在 capability span 下开一轮独立 agent 循环。
SkillLlmOptions / SkillLlmResult{ prompt?; messages?; system?; model?; maxTokens?; maxIterations? } / { text; stopReason }prompt 与 messages 二选一；system 接受 string 或 SystemPrompt。
collectSkills / skillToTool(instance) → SkillCapability[] / (capability, resolveTools) → AgentTool扫描 @Skill 方法 / 编译成主 agent 菜单项。
SkillCapability{ name; description; inputSchema; spec; invoke(input, ctx) }含绑定实例的方法执行器。
SubAgent@SubAgent(spec: SubAgentSpec) 方法装饰器方法体不执行：框架按 system 另起隔离循环，中间过程不外泄，只有最终报告回流。
SubAgentSpec{ name?; description; schema; system; tools?; model?; maxTokens?; maxIterations? }system 支持 string / SystemPrompt / (task) => SystemParam（动态拼，框架不附加）；tools 为 provider token 列表。
collectSubAgents / subagentToTool(instance) → SubAgentCapability[] / (capability, resolveTools) → AgentTool扫描 @SubAgent 方法 / 编译成 AgentTool（子循环复用 ctx.client 与 recorder）。
SubAgentCapability{ name; description; inputSchema; spec }子代理能力元数据。
Prompt@Prompt(spec: PromptSpec) 方法装饰器纯文本资产编译成无副作用的拉取型工具；每次调用重算（volatile 语义）。
PromptSpec{ name?; description; schema?; version? }description 写清何时该拉取，模型据此决定调用；schema 缺省空对象（无参资产）；version 是资产版本号 —— 装配期随能力名收集，每次 run 落 run 根 prompts.versions attribute。
collectPrompts(instance: object) → AgentTool[]扫描 @Prompt 方法（static 方法亦可）。
asset(base: string | URL, rel: string) → stringasset(import.meta.url, './system.md') 相对能力目录读文本资产；每次调用现读不缓存。
loadEnvFile(options?: LoadEnvOptions) → Record<string, string>读一份 .env 进 process.env，返回本次真正生效的键。框架不自动读 .env —— 读哪个文件、什么时候读由宿主的启动代码决定（脚手架 main.ts 首行已内置）。文件不存在静默返回 {}；真实环境变量优先，已定义的键不被覆盖（含空串）。
LoadEnvOptions{ path?; override? }path 缺省 .env（相对 cwd）；override 缺省 false（让文件压过环境变量时置 true）。
discoverProviders(dir: string | string[]) → Promise<Provider[]>给一个目录或一组目录（数组顺序即装配顺序），扫各目录下的 <name>/index.ts：default export 为类 / Provider / Provider[]，类以文件夹名为 token 注册；数组里任一目录不存在即报错，跨目录重名 token 留告警（装配期后者覆盖）。
applyMiddleware(tools: AgentTool[], middleware: CapabilityMiddleware[]) → AgentTool[]洋葱模型包裹整个菜单（链序 = 注册顺序，先注册最外层）；链为空原样返回，零开销。
CapabilityMiddleware(call: CapabilityCall, next: CapabilityNext) => unknown能力调用前后横切（鉴权 / 限流 / 缓存 / 审计 / 配额）；不调 next 即短路，抛错按能力失败处理。
CapabilityCall / CapabilityNext{ capability; input; ctx? } / (input?) => unknown入参 schema 校验已过；next(newInput) 可改写入参；连调两次会抛错。
