01 — UNITS

四类单元，一种抽象

单元即流水线的阶段。对主 agent 而言都是菜单里的可调用项，差异只在运行时执行方式。

@Tool

函数调用

类方法即工具，入参由模型按 JSON Schema 解析，运行时先校验再执行，出错回 is_error 不中断 run。

@Skill

代码控制的流程

方法体是确定性脚本，模型调用只发生在显式 ctx.llm()，返回值即产物交回主 agent。

@SubAgent

隔离的子代理

独立循环 + 裁剪上下文，中间过程不外泄，只有最终报告以 tool_result 回流主上下文。

@Prompt

纯文本资产

模板 / 宏 / playbook，模型判定需要时拉取进上下文，支持实例 volatile 与静态常量。

02 — FEATURES

为生产而生

CLI 与目录约定

agentia create 一键脚手架，agentia g 生成单元。一单元一文件夹，长文本放 .md，目录扫描与显式注册表双装配。

Trace 一等公民

runId == traceId，每次模型往返、每次单元调用都记账：token、成本、耗时、错误分类，子 agent 递归成树。

装配期静态校验

菜单跨类型查重、tools 引用存在性、DI 循环依赖——错误在启动时暴露，不留给运行时。

长上下文三策略

context editing 丢旧工具对、compaction 摘要压缩、预算护栏带滞回，CJK 感知 token 估算。

三类触发

同步 RPC、异步任务（幂等键去重、失败重提、落盘续跑）、定时调度，共用一份输入契约。

零反射装饰器

标准 Stage 3 装饰器 + 显式 DI，不依赖 reflect-metadata，tsx / esbuild / tsgo 全兼容。

units/weather/index.ts
import { Tool } from '@migor/agentia';

export default class Weather {
  @Tool({
    description: '查询城市天气',
    schema: {
      type: 'object',
      properties: { city: { type: 'string' } },
      required: ['city'],
      additionalProperties: false,
    },
    strict: true,
  })
  get_weather(input: { city: string }) {
    return `上海 72°F sunny（${input.city}）`;
  }
}
