# 官网英文版：自动检测 + 手动切换（`/en/`）

> 撰写时刻：**2026-10-08**。来源：同日「官网是不是只有中文」讨论 —— 核实结论是官网
> 全站 `lang="zh-CN"`、无 i18n 目录、无 `/en/` 路由、无语言切换；英文读者从 GitHub / npm
> （有 `README.en.md`）进来后，**一进官网就断在中文**。
> 定位判据复核：本稿**零 `src/` 改动**，全部落在 `packages/website` + `tests/docs` + `scripts`
> ⇒ 不违反「不逼核心变厚」。

## 0. 一句话

给官网补一份与中文站**逐页对应**的英文站（`/en/`），首屏按 `navigator.language` 自动落到
用户语言、Nav 提供显式切换并记忆选择；并把「语言面」并进既有的**产物守卫**——sitemap、
llms.txt、每页 markdown 变体三处此后都要求**两种语言的页面都在场**。

## 2. 路由与 URL 形态

- 中文站保持在**原路径不动**（`/`、`/docs`、`/api`、`/playground`、`/tradeoffs`）——既有外链、
  canonical、sitemap 全部零改动。
- 英文站挂 `/en/`：`/en/`（首页）、`/en/docs`、`/en/api`、`/en/playground`、`/en/tradeoffs`。
  另有 `/en/404`（对应 `404.astro` 的英文文案；**不产出 `404.md`**，与中文站同口径）。
- 实现：`src/pages/en/{index,docs,api,playground,tradeoffs}.astro` + `src/pages/en/404.astro`。
  `build.format: 'file'` 下分别产出 `dist/en/index.html` 与 `dist/en/docs.html` …
  干净形态因此是 `/en/` 与 `/en/docs`（事实 9）。**语言切换链接一律用干净形态。**

## 3. 自动检测与切换

### 3.1 检测（首屏前执行，避免闪烁）

在 `Base.astro` 的 `<head>` 里内联一段**非打包**脚本（`is:inline`，Astro 不得把它延后到
module 加载）——放在样式之前，且在 `<body>` 渲染前完成跳转判断，否则会先画中文再闪成英文。

判定顺序：

1. `localStorage['agentia-lang']`（**用户显式切换过**）优先；
2. 否则 `navigator.language` / `navigator.languages` 里是否含中文（`^zh\b`）；
3. 目标语言与当前页语言不符 ⇒ `location.replace(...)` 跳到同页的另一种语言。

**不写 localStorage 的分支**：自动跳转**只读不写** —— 否则「自动跳到 /en/」会被记成用户选择，
用户之后手动点回中文会立刻被跳回去。只有**显式点击切换**才写入。

### 3.2 切换控件

`Nav.astro` 右侧加一个语言切换（`中 / EN` 两枚，当前语言高亮、`aria-current="true"`）。
`Nav` 新增 `lang` 与 `langHref` props：由各页算出「本页在另一种语言下的地址」。
点击时写 `localStorage['agentia-lang']` 再跳转。

### 3.3 SEO 面（跳转的代价与缓解）

JS 跳转是**静态站做语言协商的唯一手段**（无服务端），代价要写明：

- **风险**：爬虫若执行 JS，`navigator.language = en-US` 会把中文首页「跳走」。
- **缓解**：① 两版页面互标 `<link rel="alternate" hreflang="zh-CN" / "en" / "x-default">`，
  且各自 `canonical` 指向**自身**（不互指）——搜索引擎据此理解「同一页的两种语言」，
  而不是「一页重定向到另一页」；② 跳转用 `location.replace`（不留历史条目）；
  ③ 检测拿不到语言（`navigator.language` 为空）时**不跳**。

## 4. fragment 组织与 docs 页 §7

- 英文 fragment 放 `src/fragments/en/*.html`，与中文 fragment **同构**（同一套 class 名、
  同一批锚点 `id`）⇒ 复用全部既有客户端脚本：`scrollspy`（靠 `id`）、`hero-trace`、
  `trace-player`、`playground-entry`。**锚点 id 一律不本地化。**
- 代码示例、`<pre>` 高亮 span、`data-*` 属性原样保留；只译散文明与标题。
- ⚠️ **docs 页 §7 边界表**：中文页仍走单源注入；**英文页不摆这张表**，改为一句说明 +
  指向单源指南的链接。理由：该表是构建期从**中文** `docs/usage-guide.md` 抠的，英文页若
  手写第二份表就必然漂移，而本仓的既定纪律是「站点上不出现第二份手写说明」。
  ⇒ 英文 `docs.html` **保留** `<!--LIMITS_TABLE-->` 占位符的**替代分支**由页面处理（见 §5）。

## 6. 守卫（新增 `tests/docs/website-i18n.test.ts`）

1. **页面集合一一对应**：中文站的每个页面在 `dist/en/` 下有对应产物（404 除外），反之亦然。
2. **`lang` 正确**：中文页 `<html lang="zh-CN">`、英文页 `<html lang="en">`。
3. **`hreflang` 互指**：两版各自含指向对方与自身的 `alternate` 链接，且 `x-default` 指中文版。
4. **切换控件在场**：每页 Nav 里两个语言的链接，且链接指向**同页**的另一种语言（不是首页）。
5. **英文页无中文散文**：对英文 fragment 抽样断言「不含 `[\u4e00-\u9fff]`」，
   但**放行代码块与允许的专有名词**（判定方式：先剥 `<pre>` 与 `<code>`）。
6. **英文页不引第二份边界表**：`dist/en/docs.html` 里不出现 `limits-table` 的表格结构。

产物守卫（§5 第 1 行）负责「英文页也有 `.md` / 链接干净 / og:url 一致」，
本文件只负责**语言面**本身 —— 两者射程不重叠。

> **落地时的两处偏差（2026-10-08，实现后回填）**
>
> ① **判据落在源码与行为上，不看 `dist/`**：`npm test` 在 `verify-all` 里**早于**官网构建
>    （步 6 vs 步 8）⇒ 在守卫里断言 `dist/` 会读到陈旧或缺失的产物。于是 1–4 条改成断言
>    `src/pages/en/*.astro`（`<Base …>` 真带 `lang='en'`）、`src/layouts/Base.astro`（`<html lang>`
>    映射与三处 `hreflang`）、`src/components/Nav.astro`（切换控件）；第 6 条改成断言
>    `src/fragments/en/docs.html` **不含** `limits-table` / `LIMITS_TABLE` ——「英文页不摆第二份表」
>    的源头就在这个 fragment（英文页没有注入逻辑），不必等构建。产物侧那半仍由
>    `scripts/check-website-agent-readiness.mjs` 在步 8 守。
> ② **第 5 条从「文本扫描」升级成「行为断言」**：`playground*.js` 的文案是**运行期**插进 DOM 的，
>    而源码扫描需要 JS 解析器 —— 本仓 `typescript` 是 7.x（tsgo），主入口已不再导出经典 parser API

## 7. trade-off 与不做什么

- **不做服务端协商**：静态托管没有服务端，`Accept-Language` 拿不到。JS 是唯一手段。
- **不做 `/en/` 的内容再做一遍文案创作**：英文页是**对译**，不是「面向英文用户的重新定位」。
  文案主张、数字承诺、边界口径必须与中文页**同一套**（否则两版会各说各话，这正是
  `stability.test.ts` 已经在防的那类漂移）。
- **不新增英文单源长文档**（用户已选）：英文 docs 页的 §7 用说明 + 链接替代，
  `llms-full.txt` 保持中文单源不动。
- **不把语言切换做成路由级重定向规则**：Cloudflare `_redirects` 无法按语言分流。
